# Module 1.1: Staying Organized 📂

## 1. Why Methodology and Structure Matter
When conducting a penetration test on a single box, a lab, or a corporate client environment, maintaining a clean and consistent folder structure is essential. During an assessment, you will generate mass amounts of data (scans, exploit scripts, logs, and screenshots). Without organization, you risk losing critical evidence, credentials, or post-exploitation data.

## 2. Professional Lab & Assessment Folder Structure
A standard and structured approach is to create a master folder for the client or project, subdivided by the type of assessment: **Internal Penetration Test (IPT)** and **External Penetration Test (EPT)**.

Here is the blueprint of a professional attack machine folder structure:

```bash
Projects/ 
└── Acme Company 
	├── EPT (External Penetration Test)
	│   ├── evidence 
	│   │   ├── credentials 
	│   │   ├── data 
	│   │   └── screenshots 
	│   ├── logs 
	│   ├── scans 
	│   ├── scope 
	│   └── tools 
	└── IPT (Internal Penetration Test)
		├── evidence 
		│   ├── credentials 
		│   ├── data 
		│   └── screenshots 
		├── logs 
		├── scans 
		├── scope 
		└── tools
```

## 3. Subfolder Breakdown
* **scope/**: Contains the lists of target IP addresses, subnets, or domains provided by the client to feed into scanning utilities.
* **scans/**: Stores raw output and reports from enumeration tools like Nmap, Gobuster, or Nessus.
* **tools/**: Dedicated directory for custom scripts, binaries, or specific exploits downloaded for this specific target.
* **logs/**: Saves command outputs, terminal logging transcripts, or reverse shell output records.
* **evidence/**: The most critical folder, split into:
    * `credentials/`: Text files containing discovered cleartext passwords, hashes, or SSH keys.
    * `data/`: Infiltrated files, configuration documents, or database dumps from the victim.
    * `screenshots/`: Visual proof of successful exploitation, user flags, and administrative/root access.
